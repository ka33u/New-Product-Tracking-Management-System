# 亨达新品开发

依据《产品开发控制程序》及 HD/JL-SJ-01A1～10A1 表单重构的电机新品开发系统。系统以“项目 → 同系列多个电机规格 → 10 个阶段 Sheet”为主线，贯通销售订单、设计输出、零部件节点、试验报告、质量检验、客户试用、鉴定、变更和完整归档。

源码仓库：[New-Product-Tracking-Management-System](https://github.com/ka33u/New-Product-Tracking-Management-System)（new motor）。仓库仅保存程序、迁移、测试和开发文档，不包含实际账户、业务数据库、上传附件、备份、密钥或本地封存运行包。克隆源码不等于恢复现有业务数据，也不会自动配置这台电脑的保活服务；新电脑请按下文部署，数据迁移另按备份恢复说明操作。

## 核心能力

- 项目打开后展示“项目概览 + 10 个阶段 Sheet”，每个 Sheet 有责任角色、计划节点、状态、进度、版本、附件和操作时间戳。
- 看板、项目表格/卡片及阶段页面统一展示对应岗位的全部已分配成员；当前账号停用时明确标注，无启用成员则提示待分配。读取新数据后反映改名/转岗/重新启用，同名不同账号仍独立保留，不把项目负责人自动当作各阶段责任人。阶段页提供分配指引；这是当前分工提示，不修改阶段进度、历史快照或授予权限。其他人的变更需刷新页面读取，暂不实时推送。
- 一个项目可包含多个同系列具体电机规格，每个规格分别维护检验要求、试验要求、计划节点、试验报告和整机检验记录。
- 八类登录角色：管理员、销售、设计、工艺、采购、生产、试验员、质量。仅销售、设计、管理员可建项；管理员查看全部，其他人员查看自己发起、负责或被分配参与的项目。
- 发起人自动取创建人，建项时必须指定项目负责人、工艺、采购、生产、试验和质量责任人。
- 销售订单台账支持录入、客户一致性校验、一个项目关联多个订单、解除/重关联及交付日期跟踪。
- 生产确认整机和零部件节点；试验员按规格提交型式/验证报告；质量人员提交整机和零部件检验记录。
- 质量检验要求由设计输出自动引用，后续检验记录不能脱离或自行篡改要求来源。
- 项目总看板支持负责人筛选、年度、半年度、月度、自定义区间和个人指标配置。卡片、状态分布、周期流量和重点项目共用筛选，纳入跨期未结项目；区分按期完成与未结逾期，终止项目不计当前逾期。流量按北京时间登记/完成日期归桶，可展开精确明细及统计口径。详见 [看板口径](docs/dashboard-metrics.md)。
- 阶段门校验前置 Sheet、受控表单、零部件完工、规格级试验和质量记录齐套性。
- “我的任务”和侧栏数量共用同一模型，按当前账号、项目可见范围及既有阶段维护权限归集，工艺/采购协作阶段也纳入。草稿/进行中项目的未完成阶段计待办，含后续计划；暂停任务单独保留供查看，恢复后重新计入，已完成/已终止项目退出待办。按北京时间判断逾期，缺失/无效日期排末并提示，不当作逾期；暂停不顺延计划。“我维护的已完成阶段”仅统计当前已完成且最后维护人为本人的可见阶段，不是历史完成次数。任务分类不会更改项目状态或放行权限。
- 支持标准 `.xlsx` 项目概览及单项目多工作表导出，包含完整项目日志和分段历史快照。进度/数量/金额/日期保留Excel类型，时间戳显示北京时间，附件为索引而非原件。概览导出按权限导出全量，不应用页面筛选。单 Sheet 及完整开发程序 Word 使用原生 `.docx`，包含当前记录、各阶段版本变更摘要与附件索引；不内嵌原始附件，不是原纸质表单的版式复刻。
- 项目页“离线归档 ZIP”包含程序Word、完整项目Excel、全部附件原件和对应清单。重名原件按序号独立保留，超长/不安全文件名处理后原名仍记在清单。缺失或不一致附件拒绝归档，读取中变更/截断会中止下载；附件逐个流式读取，标准ZIP上限为4GB及65535项（含4个说明/数据文件）。项目结构化数据和权限以同一次只读事务为准，清单分别标明数据读取及文件生成时间；后续修改不进入已生成包。附件原件的读取不属于数据库事务。归档未加密，不等同签章审批、整库备份或导入恢复。详见 [离线归档说明](docs/project-bundle.md)。
- D1 保存业务数据，R2 保存附件；所有写操作由服务端再次校验权限并写入审计时间戳。

详细架构见 [系统蓝图](docs/system-blueprint.md)，验收证据见 [完成度审计](docs/completion-audit.md)，正式使用前逐项核对 [本地使用验收清单](docs/local-acceptance.md)。

## 本地运行

环境要求：Node.js `>=22.16.0`。

HTTP 新建项目白屏与 Windows 重启反馈的修复范围、隔离测试及已有安装更新步骤，见 [Issue 修复与复测](docs/issue-fixes-2026-09-10.md)。迁移失败仍拒绝启动，不通过删除数据或跳过迁移处理启动异常。

```bash
npm install
npm run build
npm run start:local
```

系统启动后访问终端显示的本地地址。首次部署显示管理员初始化页面，由部署人设置姓名、邮箱和密码，不再自动以管理员身份登录。管理员随后在“人员权限”中新建账户；本地初始密码必填，界面与接口均校验，避免创建无法登录的账户。已有未设置密码的旧账户需由管理员维护密码后才能登录。会话有效期为 8 小时，退出后立即注销。重置密码、停用账户、改变角色或登录邮箱会撤销该账户现有会话。

工作区刷新遇到未登录或已失效会话会明确提示重新登录，不再误报初始化。请先保留窗口中未保存的内容，再刷新页面登录；页面刷新不会自动保存草稿。工作区响应禁止缓存，当前登录人员资料与业务列表来自同一批读取结果。

本地业务保存和上传会核对页面当前显示的账号与实际登录账号。另一标签页切换账号后，旧页面的提交会被拒绝，不会记到新账号名下；工作区刷新也不会把另一账号的数据替换进正在填写的窗口。先复制留存未保存内容，再刷新并确认账号。此次更新前已经打开的旧页面也需先保留输入再刷新一次。

程序化调用本地 `POST /api/action`、`POST /api/files` 时，除会话和同源要求外，须在 `X-NPD-Actor` 请求头携带页面/调用方已确认的当前用户ID。缺失或不一致返回409/`ACTOR_CONTEXT_CHANGED`；该请求头不是身份凭据，也不授予任何权限，不能代替登录或服务端角色校验。未登录仍返回401。登录、退出与只读下载不使用这个业务写入前置条件。

新部署的空数据库默认不插入演示人员、客户、订单或项目。先初始化管理员，再在“人员权限”录入销售、设计、工艺、采购、生产、试验、质量人员；在“客户资料”新增客户，然后录入订单并创建项目。演示数据仅在隔离测试中显式启用。

登录尝试受持久化限速保护：同一邮箱（忽略首尾空格和大小写）每15分钟最多10次、本机总计每分钟60次，首次管理员设置每15分钟5次。成功及失败都占用尝试次数；达到上限显示等待时间，到期可重新尝试，不会永久锁定账户或中断已有会话。计数写入本地数据库，重启不能绕过；过期记录会在后续尝试时清理。请勿通过反复刷新/重启或更换邮箱连续尝试。

登录表单最多8KiB，超长提交会被拒绝。密码验证与新会话写入再次核对账户有效性及凭据；验证期间发生停用/密码重置时不会签发旧凭据会话，失败也不写入成功登录记录。正常登录只更新“最后登录时间”，不会触发账户资料的编辑冲突。

账户维护使用独立递增版本号，同时核对窗口打开时的资料。即使同一秒重置密码、资料改动后又改回原样，旧窗口也不能覆盖新版本；遇到冲突会保留输入，请重新打开最新账户核对。审计记录账户前后版本、资料变更和密码重置事件，不记录密码、盐或哈希。版本从本次升级时开始记录，不能补回升级前未保存的历史。

项目成员职责与销售订单关联也使用独立版本号。分配成员、关联/解除订单及建项选单均携带窗口打开时的版本；“改了又改回”仍会识别为变化，旧窗口拒绝覆盖并保留输入。成员按记录独立校验，不同成员的职责修改不必互相阻塞；同一成员相同内容的并发提交只允许一次成功。新建订单和成员从V1开始，建项关联订单也递增订单版本。版本、关联/职责修改与审计在同一事务内保存；升级仅为旧记录增加V1，不重置原数据，也不会补回此前未记录的版本历史。

升级不会删除现有数据库中的演示或业务记录；请逐项核对后再正式使用。不要删除 `.wrangler/state`，其中保存本地数据库和附件。

本地构建配置显式设置 `NPD_AUTH_MODE=local`，正式构建不再因 `NODE_ENV=production` 自动改走 ChatGPT 身份。`start:local` 通过 `scripts/local-server.mjs` 直接启动已编译 Worker，不经过 Wrangler 开发代理。只监听 `127.0.0.1:3011`，沿用原 D1/R2 绑定标识及 `.wrangler/state/v3` 数据位置。不要与另一服务共用端口或数据库。启用固定版本后，从 `.local-releases/<版本>/` 加载已选的Worker、资源、运行器和迁移，重新构建dist或重启不会自动选用新构建；须准备候选、隔离验收、备份、显式切换再重启。目录只读并在启动时校验，保护常见误改而非防御本机管理员。首次未选固定版本时保留dist兼容入口，已启用后丢失指针则拒绝回退。详见 [本地版本更新说明](docs/local-releases.md)。尚未进行整机重启/断电恢复演练。

`npm start` 仍是通用 Vinext Node 服务命令，不作为此项目D1/R2本地部署入口。`npm run dev -- --port 3011` 仅供开发调试，不应与日常服务并行。`npm run test:production-runtime` 显式检查当前dist构建，使用同一个正式本地入口、随机端口和独立临时数据库；设置 `NPD_TEST_RELEASE=<版本标识>` 时改测指定候选，均不触碰现有3011业务数据。

工作区只加载历史版本目录，需要时再读取完整版本正文；项目归档仍保留全部已记录历史。`npm run test:workspace-scale-runtime` 在强制新建的临时库验证100项目、1,000规格和1,000历史版本的读取、并发刷新、权限及大表Excel无损导出，也支持 `NPD_TEST_RELEASE`。Excel压缩已适配本地Worker不支持创建子Worker的限制；升级构建工具或导出依赖后必须重跑该真实运行时测试，普通Node导出测试不足以覆盖此兼容问题。此用例不是最大容量或长期负载保证。

从新增迁移 `0005_new_quasimodo` 起，本地新增表由 `scripts/local-migrations.mjs` 执行生成的Drizzle SQL，不在请求处理过程中创建。启动前按迁移名和校验值记录，失败整体回退，已执行文件内容不一致则停止启动；历史0000～0004仍保留旧本地初始化兼容逻辑，不盲目重放。开发命令也会先执行增量迁移，首次开发需先构建以生成本地绑定配置。不得改写已应用迁移；后续改表应新增迁移并纳入本地迁移清单。

依赖安全检查使用 `npm run security:audit`（需联网）。命令包含开发和间接依赖，查询失败会明确失败，不将离线安装显示的“0 vulnerabilities”作为安全结论。剩余上游风险及当前检查范围见完成度审计，不能据此宣称系统没有漏洞。

安全检查另补查vinext已知布局中的内嵌image-size代码，以防依赖被打包后从npm依赖图消失而误报风险已清零。npm包数量和内嵌发现分开列出；这不是完整供应链扫描。已排除直接升级预发布版作为高等级告警修复的方案，详见[依赖安全评估](docs/dependency-security.md)。

构建配置通过公开接口禁用ICNS、HEIF（含HEIC/AVIF）及JPEG XL尺寸解析，`npm test`先执行真实配置/框架路径的有界回归。此限制不改变业务附件上传和归档规则，也不表示依赖漏洞已修复；程序图标请使用受支持的PNG/JPEG/SVG等格式。正式验收仍须处理安全告警及核实适用边界，不能删除警告来获得“通过”。

迁移工具的旧esbuild分支已定向覆盖到0.25.12；其他编译器和框架版本不变。默认测试增加 `test:migration-tooling`，在临时目录检查实际转译、当前结构无变化、合成增量迁移和旧数据保留，不改真实迁移或业务库。当前公开检查为0中等、2高，详见上述安全评估；旧依赖恢复副本需受控保留，不能直接混用不同锁文件和运行版本。

## 数据备份

这台电脑已配置自动保活服务，使用 `npm run backup:local:managed` 可核实并暂停本项目服务，生成数据库与附件成套备份，再自动重新启动。手动运行的实例应先停止服务，再运行 `npm run backup:local`。恢复只允许写入不存在的新目录，不覆盖现有业务数据。详见 [本地备份与恢复说明](docs/local-backup-recovery.md)。备份包含敏感资料且未加密，请妥善保管并另存到受控磁盘。

## 变更与证据规则

- 在项目概览的“项目团队”中可办理“负责人交接”。发起人、当前负责人或管理员填写接任人员、新旧职责、原因及未完成事项；已完成/终止项目仅管理员可办。暂停期间可以交接，但不会恢复项目。接任人员须为启用的销售、设计或管理员；原负责人停用时，管理员不必重新启用旧账户就能交接。新旧职责、成员版本、负责人、独立交接版本与审计整体保存，任一步失败均回退。旧窗口、负责人改回原人、成员职责已变或接任账户提交前停用均拒绝覆盖。
- 交接后原负责人保留项目成员身份，不等于删除账户或撤销全部权限；发起人和管理员仍保留各自管理权限。接任人立即取得项目维护权限，看板负责人筛选及项目/归档中的当前负责人同步更新；阶段责任角色和既有报告签署人不随交接改写。交接记录在项目操作日志中保留，旧项目新增交接版本从V1开始，不补造历史。阶段请求在前期授权后发现交接版本变化，或提交前发生交接，也会拒绝保存。
- 项目暂停、恢复、终止使用独立状态版本，窗口固定打开时的版本；“暂停后恢复原状态”也不能让旧状态决定覆盖新决定。每次变更在同一事务保存状态版本、原因与审计；自动结项或管理员通过阶段重开引起项目状态变化也递增，普通进度维护不递增。旧项目升级从V1开始，不补造历史。阶段请求在校验后、事务提交前发生状态往返，或提交时成员访问权限已被撤销，也会拒绝保存。此保护不是所有旧编辑窗口的统一项目锁或历史回滚功能。
- 表单、阶段状态、电机和零部件修改携带编辑起始版次。遇到旧版或并发冲突时拒绝覆盖，并保留窗口内的填写内容；请先保留需要的文字，再关闭并重新打开最新版本核对。没有强制覆盖按钮。
- 上述修改以及新增规格/零部件、生产确认的业务内容、操作记录、阶段版本、下游复核及总进度使用同一数据库事务；任一步失败会整体回退。其他业务路径仍在逐项迁移与验收，不能把此保证推广到所有操作。
- 同一规格范围内（含系列通用件）的零部件编号不能重复；生产确认会核对设计版次和节点版次，旧设计不能直接确认到新版。
- 电机和零部件修改升级设计版次，保留变更原因、操作者和时间；已完成下游阶段转为待复核。
- 新增的阶段版本保存业务内容快照，规格、要求、零部件和表单修改还保留修改前内容。升级前未记录的历史内容无法补回。
- 试验与质量阶段标记完成前，核验当前设计版次最新有效报告对应的附件原件。原件缺失、大小不符、路径归属异常或存储不可用时拒绝放行且不产生阶段修改；核验后数据库索引或设计版次发生并发变化也会拒绝。成功版本保存原件ID、名称、大小、ETag及核验时间，可在版本详情查看，原始快照也随项目Excel归档。此项是放行时存在性/大小核验，不是病毒扫描、数字签章、持续完整性监控或数据库与文件存储的跨系统事务；放行后被外部删除的文件不会自动使历史阶段变更。旧版本不补造核验凭据。
- 试验要求自动取当前电机设计输出。每个报告类型分别取当前设计版次的最新记录；不能用另一种试验的合格结果覆盖未通过的试验。
- 试验、质量阶段进度与放行使用相同证据规则：当前版次、可接受结论、报告附件、要求一致。缺附件的记录可以登记，但不计入有效齐套数。
- 有条件合格、让步接收必须填写处置依据。阶段仍需人工复核后放行，不会仅因上传报告自动完成。
