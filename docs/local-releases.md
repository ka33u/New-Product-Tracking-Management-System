# 本地固定运行版本

日常服务由原来的 `npm run start:local` 启动，端口仍为127.0.0.1:3011，数据仍在项目的 `.wrangler/state/v3`。启用固定版本后，Worker、页面资源、运行器和增量迁移脚本/SQL均从 `.local-releases/<版本>/` 读取，不从重新构建中的dist读取。目录设为只读，减少误改；这不是对本机管理员的安全边界。

## 更新步骤

1. 保留现有运行版，修改源码并执行完整构建、回归测试。第一次启用前服务仍使用dist，应暂停托管服务后构建；启用后普通重建不会切换运行版。
2. `npm run release:local -- prepare`：复制当前构建、运行脚本、迁移文件、package.json和锁文件，校验复制前后内容，生成候选版本。记录输出的版本标识。准备不是验收，也不会启用候选版本。
3. 运行候选版本隔离验收：`NPD_TEST_RELEASE=<版本标识> npm run test:production-runtime`。它使用独立临时数据目录和随机端口，不写入现有项目。`npm run test:local-release-runtime` 另验证覆盖构建/运行器/迁移来源后仍能正常访问与重启。
4. 确认全部验收通过，暂停同一托管服务、等待数据库句柄关闭并生成D1/R2备份，然后执行 `npm run release:local -- activate <版本标识>`，重新启动原服务并检查首页、业务数据和迁移记录。切换命令只原子更新版本指针，不自动停止、启动、备份或回滚数据库；不能省略这些步骤。
5. `npm run release:local -- status` 检查当前配置的固定版本；`verify <版本标识>` 校验一个候选。配置的版本在下一次启动时生效，不能将status输出等同于正在运行进程的版本。启动日志记录实际选择的版本标识。

开发验收如要使用当前dist，应显式使用 `node scripts/local-server.mjs --build --port 0 --state <隔离目录>`。不要把该模式用于日常业务服务。`--release <版本标识>` 可试跑指定固定版本；不要与现有服务共用数据库目录。

## 防误切换

- 启动前逐个核对版本文件的长度和SHA-256清单，拒绝缺失、改写、额外文件、不安全路径和符号链接。
- 核对Node精确版本、Miniflare声明版本和当前锁文件摘要。共享node_modules并没有被完整复制或逐文件签名，不能宣称整个操作系统/依赖环境已冻结。改变依赖或Node前应安排维护窗口；旧版本重启可能因环境不匹配被拒绝，须重新构建验收新版本。
- 当前版本与候选版本的DB/R2绑定必须一致，已有迁移必须存在且哈希相同；不能通过切换旧软件回退已经升级的数据库。发生有迁移的失败升级时，应使用成套备份恢复到新数据目录并按恢复流程核验，不对现有库盲目降级。
- 版本指针采用同目录临时文件加重命名，切换有互斥锁。已启用固定版本后若指针丢失，拒绝回退到dist。错误指针、损坏目录或残留切换锁需要维护人员依据日志和备份核实，不自动猜测或删除。
- 校验防止常见误改，不等同数字签名、磁盘故障保护或对本机管理员的防篡改承诺。没有自动删除历史版本或未完成的`.preparing-*`目录，也没有后台自动升级。

## 备份边界

原有D1/R2备份保留业务数据，不自动包含软件固定版本。受控备份应同时保留项目源码/依赖锁文件、要恢复的软件版本目录和业务备份。版本目录不存放项目数据库或上传附件，但包含企业业务程序，仍应受控保存。运行版本的默认选择指针不属于数据库备份，也不会在业务恢复时自动切换。

## 验收证据

- `tests/local-release.test.mjs`：复制隔离、只读文件、依赖变化、内容损坏、符号链接、指针丢失、数据库绑定变更、旧迁移改写和并发切换。
- `tests/local-release-runtime.mjs`：真实本地Worker的隔离目录，覆盖来源构建、运行器和迁移，再访问/重启，旧资源仍一致。
- `tests/local-production-runtime.mjs`：指定候选版本的账户、权限、业务写入、静态资源、上传下载和Word/Excel/ZIP全套HTTP回归。

不是浏览器交互/像素验收、整机断电恢复或长时间压力测试。每次实际部署结果以完成度审计记录为准。
