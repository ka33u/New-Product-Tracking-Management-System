# 本地数据备份与恢复

适用于本项目当前 macOS 本地版本。备份工具需要 Node.js 22.16 或更新版本，并使用 macOS 自带的 `lsof` 检查数据文件是否仍被使用。无法确认停用时会拒绝备份。

## 备份包含什么

- `.wrangler/state/v3/d1`：账户、项目、阶段表单、版本记录、进度、审计记录等数据库。
- `.wrangler/state/v3/r2`：附件存储索引和文件内容。
- 清单：备份时间、文件大小、SHA-256 校验值、数据库记录数量。

不包含程序源码、Node.js、依赖包、环境配置、外部服务数据。请同时保留与备份配套的整个程序及 `package-lock.json`。Excel/Word 导出不能替代这份完整数据备份。

备份包含个人信息、企业技术资料和密码哈希，**并未加密**。新建备份包仅当前 macOS 用户可读写，仍应放在受控磁盘中，不要发到公开网盘或聊天群。校验值用于发现损坏，不代表备份来源可信；只恢复本单位保管的备份。

## 生成备份

这台电脑已配置 `com.hengda.npd.local` 自动保活服务，单独结束进程会自动重启。使用下面的专用命令会核实服务属于本项目，再暂停它、生成备份，最后重新启动；执行前请通知人员保存并暂停操作：

```bash
npm run backup:local:managed
```

如果使用的是终端手动启动的服务，而不是上述托管服务，按以下步骤操作：

1. 通知使用人员保存操作并退出，停止运行本地服务的终端进程（终端中按 Control+C）。仅关闭浏览器不会停止服务。
2. 在本项目目录执行：

```bash
npm run backup:local
```

3. 成功后显示 `backups/hengda-时间-后缀` 的完整路径。工具会备份 SQLite 的已提交数据，而不是仅复制可能遗漏日志的主数据库文件；逐个校验数据库完整性、外键、文件哈希和记录数量。若源数据在过程中改变则不生成成功备份。
4. 重启服务：

```bash
npm run start:local
```

5. 将成功的**整个备份目录**复制到另一块受控磁盘，再对复制后的目录验证：

```bash
npm run backup:verify -- "/绝对路径/备份目录"
```

不要遗漏 `manifest.json` 或 `state` 子目录。工具不删除旧备份、不覆盖同名备份。普通 `backup:local` 不会自动停机，`backup:local:managed` 会暂停本项目的托管服务并在结束时恢复。失败产生的 `.incomplete-*` 目录不能当作成功备份使用，可由管理员核实后处理。

如命令明确提示“托管服务重启失败”，不要重复创建备份或删除数据。先校验已生成的备份目录，再让管理员检查 `launchctl print gui/501/com.hengda.npd.local`。本机若显示服务不存在，可执行 `launchctl bootstrap gui/501 /Users/zhangyu/Library/LaunchAgents/com.hengda.npd.local.plist` 恢复，随后确认首页可访问。这里的用户ID和路径仅适用于当前电脑，不可直接套用到其他电脑。

建议每个工作日结束、系统升级前、批量数据变更前备份。这里仅提供手动备份，不代表已安装自动定时任务。

## 恢复演练（推荐先做）

选择一个**尚不存在**的新目录，且其父目录已存在：

```bash
npm run backup:restore -- "/绝对路径/备份目录" "/绝对路径/新恢复目录"
```

工具先验证备份，随后复制至新目录，校验复制结果，清除恢复副本中的旧登录会话。它不会覆盖当前 `.wrangler/state/v3`。原备份、原数据库都保持不变，恢复副本仍使用备份时的账户密码，需要重新登录。

失败时不要启用不完整恢复目录。修复问题后使用另一个新目录重试；工具不会自动删除或覆盖第一次的结果。

## 将已确认的恢复副本启用为本地数据

此步骤会把业务数据切换至备份时点，应由管理员明确批准后操作：

1. 停止本地服务，记录并保管当前数据目录。
2. 在 Finder 中把原 `.wrangler/state/v3` 重命名为带时间的保留目录，**不要删除**。
3. 把已通过校验的恢复目录移到 `.wrangler/state/v3`。该目录内部应直接是 `d1`、`r2`，不能多嵌套一层 `state`。
4. 使用配套程序启动本地服务，重新登录。
5. 核对项目数、人员、关键 Sheet、历史版本及至少一份附件下载，进行一次测试项目写入并重启确认保存。业务确认无误前不要丢弃切换前数据。
6. 如恢复验证失败，停机后把恢复副本移到另一个保留位置，再把原目录移回 `v3`；不要相互覆盖。

## 已提供的自动测试

```bash
npm run test:backup
npm run test:backup-runtime
```

第一项验证完整性、恢复数据、旧会话撤销、运行中数据库拒绝备份、损坏文件拦截、禁止覆盖、路径越界及符号链接拦截。第二项在独立临时目录启动真实本地 D1/R2 运行时，备份后重新启动恢复副本，验证账户、项目和附件内容逐字节一致。测试不会读写当前业务数据库。

这些测试证明当前存储版本的备份恢复路径，不替代升级版本后的再次演练，也不代表所有业务流程已完成验收。
